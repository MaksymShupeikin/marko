# Marko + Metis repository instructions

## Response style

Answer plainly. Report what you changed, what you verified, and what is still
broken or unverified.

**Do not emit the Section 15.1 `STAGE_RESULT` / `BLOCKERS` / `NEXT_STAGE` /
`STOP_GATE_*` footer, and do not emit a Section 16 `MACHINE_READABLE_SUMMARY`
YAML block.** That contract is retired for ordinary work: it buried the actual
answer under several hundred lines of manifest. The governance code and its
tests stay in the repository, and the validators below remain available for
whoever explicitly asks for a formal stage report — but nothing is generated by
default, and no response is expected to end with a stop gate.

Keep the honesty the old contract was aiming at, in ordinary prose:

- Say which claims you actually executed and which you only read.
- Name what you did not verify instead of implying full coverage.
- State blockers and who owns them.
- Never claim production readiness from a local run.

## Repository layout

- `backend/` — FastAPI API, Celery workers, PostgreSQL, prom.ua ingestion.
  The pure pricing domain lives in `backend/src/metis/pricing/`; the
  application lives in `backend/src/marko/`.
- `frontend/` — Flutter web client. See `frontend/AGENTS.md` for its
  conventions.
- `docs/` — architecture, pricing engine, runbook, and stage records.

## Working on the backend

Development and tests run in Docker:

```bash
docker compose up -d --build db broker migrate api worker \
  store-sync-worker pricing-worker scheduler
docker compose --profile test run --rm --build backend-test
```

With a host `.venv` present:

```bash
cd backend
PYTHONPATH=src .venv/bin/python -m pytest -q
```

**A code change reaches the running stack only after the affected container is
rebuilt.** The workers run their own image, so a fix in `backend/src` that is
not followed by `docker compose up -d --build worker store-sync-worker` leaves
scraping and pricing on stale code. That has already produced store syncs that
failed on a pagination redirect the source tree had long since handled.

## Working on the frontend

```bash
cd frontend
dart format lib test
dart analyze
flutter test
```

`flutter analyze` crashes in this checkout because the directory name contains
a non-ASCII character; `dart analyze` reports the same diagnostics and works.

No generated `.g.dart`/`.freezed.dart` files, no `lib/app`, no `lib/shared`.

## Formal stage reports (only when explicitly requested)

The Section 15/16 typed models, renderer, and validators are in
`backend/src/marko/governance/`, documented in
`docs/PROMPT_15_012_END_OF_RESPONSE_CONTRACT.md` and
`docs/PROMPT_15_013_MACHINE_READABLE_SUMMARY.md`, with worked examples in
`docs/examples/`.

```bash
cd backend
uv run validate-response-footer --manifest MANIFEST.yaml --render
uv run validate-machine-summary --manifest MACHINE_SUMMARY.yaml
```

Use them when someone asks for a stage report. Do not use them otherwise.
