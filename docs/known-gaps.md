# Разрывы «должно / есть»

Живой список: сюда пишем расхождения между спекой и кодом, отсюда берём
задачи. Всё ниже проверено по коду, не предположения.

Порядок = приоритет. G1–G3 объясняют, почему у живого пользователя всё
работает хуже, чем во время проверок агентом: агент дёргает API напрямую,
с полным набором параметров, а человек проходит через UI, который эти
параметры теряет.

---

## G1. В карточке товара нет проверки цен

**Должно:** открыл товар — сразу видишь рынок (`ui-behavior.md` §3).
**Есть:** `_CompetitorsPlaceholder` — статичный текст «з'явиться тут».

- `frontend/lib/features/products/widgets/product_details_panel.dart:123,478`

Главный сценарий продукта в интерфейсе отсутствует. Всё остальное —
подготовка к нему.

## G2. UI не передаёт название товара в поиск по avto.pro

**Должно:** `GET /api/v1/competitors/avtopro?oem=&brand=&name=` — параметр
`name` нужен, чтобы отсечь чужую марку, когда номер висит на нескольких
(`parser-spec.md` §3, правило 2).
**Есть:** клиент отправляет только `oem` и `brand`.

- `frontend/lib/features/products/products_api.dart:63` — в запросе нет `name`
- `frontend/lib/features/products/products_controller.dart` —
  `CompetitorSearchController.search(oem, {brand})` не принимает название
- бэкенд параметр принимает и умеет им пользоваться:
  `backend/src/marko/api/routers/v1/avtopro.py:30`,
  `backend/src/marko/parsers/avtopro/gateway.py: pick_suggestion`

Результат: при пустом бренде выбирается top-1 выдачи avto.pro, а он, по
комментарию в самом коде, регулярно чужой («China», «BENTLEY»). Отсюда
ощущение, что «парсер врёт», хотя парсер получил недостаточно данных.

## G3. Бренд и OEM пользователь вбивает руками

**Должно:** поля подставляются из товара, ручной ввод — только для разовой
проверки постороннего номера.
**Есть:** модал «Ціни конкурентів» открывается пустым; чтобы им
воспользоваться, нужно самому знать OEM и бренд.

- `frontend/lib/features/products/widgets/competitor_results.dart:134`

## G4. Импорт: непонятно, сколько осталось

`progress_total` выставляется **в конце** импорта (значением уже
импортированного), поэтому во время работы процент и остаток посчитать
нельзя — виден только растущий счётчик.

- `backend/src/marko/services/catalog_import.py:101,113-114`

## G5. Импорт: прогресс живёт только в модале

Опрос задачи продолжается после закрытия модала, но нарисован прогресс
только внутри `source_panel`. Закрыл окно — статуса нигде нет.

- `frontend/lib/features/products/widgets/source_panel.dart:110`

## G6. XLSX: «пропущено N» без причины

Ответ импорта содержит только `imported` и `skipped`. Почему строка
пропущена (нет ссылки, нет цены, битый формат) — не знает ни пользователь,
ни разработчик.

- `backend/src/marko/api/schemas/stores.py:13`
- `backend/src/marko/services/catalog_import.py: import_export_file`

## G7. Фильтр цены молча глотает мусор

`double.tryParse` вернул `null` — фильтр просто не применяется, поле выглядит
заполненным. Пользователь думает, что фильтрует, а видит весь каталог.

- `frontend/lib/features/products/products_page.dart: CatalogPriceRange._parse`

## G8. Лента avto.pro читается на 2 страницы

`max_search_pages=2` в API. Если лента отсортирована не по цене, минимальная
цена может остаться за пределами выборки, и «минимум рынка» будет неверным.
Нужно проверить сортировку ленты и зафиксировать решение в `parser-spec.md` §3.

- `backend/src/marko/api/routers/v1/avtopro.py:36`

## G9. Порог похожести подобран на глаз

`similarity_threshold = 0.55` ничем не измерен. Нужен размеченный набор пар с
реального каталога, иначе матчинг нельзя ни улучшить, ни защитить.

- `backend/src/marko/parsers/prom/config.py`

## Как закрывать

Одна задача = один пункт. Задача закрыта, когда:

1. поведение совпадает со спекой (`ui-behavior.md` / `parser-spec.md`);
2. проверено **через интерфейс на реальных данных**, а не только тестами;
3. пункт удалён отсюда или переписан с новым статусом.
