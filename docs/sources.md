# Источники товаров

Каталог наполняется двумя способами. Оба пишут в одни и те же `listings`, потому
что магазин определяется по `(marketplace, external_id)`.

## Prom.ua по ссылке

`POST /api/v1/stores` ставит задачу в Celery, worker обходит публичные страницы
продавца. Подробности парсера — в `parsers/prom`.

## XLSX-выгрузка Prom

`POST /api/v1/stores/import-file` (multipart, поле `file`) принимает файл из
кабинета продавца и импортирует его синхронно: 5 тыс. строк укладываются в
пару секунд.

Читается лист `Export Products Sheet` (если его нет — первый лист). Колонки
находятся по названию заголовка, порядок не важен:

| Колонка файла | Поле listing |
| --- | --- |
| `Унікальний_ідентифікатор` | `external_id` |
| `Назва_позиції_укр`, иначе `Назва_позиції` | `name` |
| `Ціна`, `Валюта` | `current_price`, `currency` |
| `Код_товару` | `sku` |
| `Виробник` | `brand` |
| `Наявність` | `is_available` (`-` означает «нет в наличии») |
| `Посилання_зображення` | картинка в `raw_data` |
| `Продукт_на_сайті` | `url` и определение магазина |

Магазин берётся из хоста товарных ссылок: `kemp-cs2847093.prom.ua` означает
продавца `2847093`, то есть тот же магазин, что создаёт импорт по ссылке.
Повторная загрузка обновляет существующие товары, а не плодит новые.

### Номера запчастей

Номер нужен для проверки цен на avto.pro, поэтому собираются все варианты:
`Код_товару`, `Номер_пристрою_(MPN)` и характеристики `Код запчастини` и
`Кросс-номери`. Значения приводятся к верхнему регистру без пробелов,
дедуплицируются с сохранением порядка, слишком короткие отбрасываются.
Результат лежит в `listings.raw_data->'oem_numbers'`, лучший номер первый.

На реальной выгрузке (4901 товар) номер есть у всех позиций, у 84 % их больше
одного.
