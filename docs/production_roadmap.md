# Дорожная карта до продакшна

Документ отвечает на один вопрос: что означает перевод Marko из `development`
в `production` и что для этого нужно сделать. Всё изложенное проверено по коду,
а не по памяти: ссылки на файлы указаны, чтобы каждое утверждение можно было
перепроверить.

## 1. Что переключается

В `.env` есть строка `ENVIRONMENT`. Она **не влияет на расчёт цен**: формула,
пороги, гейты сопоставимости и правило «минимальная допущенная цена минус 5%»
одинаковы в обеих средах. Она меняет только то, **насколько строго приложение
проверяет само себя перед запуском**.

| | `development` (сейчас) | `production` |
|---|---|---|
| Основание для выпуска цены | флаг владельца в `.env` | подписанный приёмочный артефакт |
| Поведение при нарушении | приложение работает | приложение **не стартует** |
| Документация API | открыта | закрыта |
| Хосты и CORS | звёздочка допустима | только явный список |
| Внутренние вызовы LLM | допустим HTTP | только HTTPS |

## 2. Что именно проверяет `production`

Проверки собраны в одном месте — `backend/src/marko/core/config.py:505-533`.
Если хотя бы одна не выполнена, приложение падает при старте с понятной
ошибкой, а не работает «наполовину»:

- `DEBUG=false`;
- `ALLOWED_HOSTS` — непустой явный список, звёздочка запрещена;
- `CORS_ORIGINS` — без звёздочки;
- `FIREBASE_PROJECT_ID` заполнен;
- если включён флаг `PRICING_COMPARABILITY_V1_AUTOMATIC_ENABLED`, обязаны быть
  заданы **и путь к артефакту, и его SHA-256**
  (`PRICING_COMPARABILITY_ACTIVATION_ARTIFACT`, `..._SHA256`).

Первые четыре пункта — работа на полчаса. Пятый пункт и есть настоящая дорожная
карта.

## 3. Почему артефакт нельзя просто «выписать»

Артефакт — это JSON-файл, но приложение не верит ему на слово. Проверка идёт в
три слоя (`backend/src/marko/services/comparability_activation.py`):

1. **Побайтовый хеш.** SHA-256 файла обязан совпасть со значением в `.env`.
   Дописать строку в файл нельзя — хеш изменится.
2. **Содержимое.** Внутри должны лежать результаты двух приёмочных прогонов —
   `locked` и `shadow` — со статусами `LOCKED_ACCEPT` и `SHADOW_ACCEPT`, каждый
   со своим внутренним хешем, который тоже пересчитывается при валидации.
   Подменить результат внутри файла нельзя — не сойдётся вложенный хеш.
3. **Совпадение с реальностью.** В артефакте записан «отпечаток среды»:
   версия контракта, версия схемы, версия промпта, провайдер, идентификатор
   модели и хеш её настроек. Он сверяется с тем, что реально запущено
   *сейчас*. Артефакт, выпущенный для другой версии промпта или другой модели,
   считается недействительным.

Плюс требование к людям: в артефакте фиксируются **два разных человека** —
владелец продукта и владелец риска (`product_owner_id ≠ risk_owner_id`),
решение `APPROVE` и дата с часовым поясом. Один человек подписать выпуск за
обоих не может.

## 4. Что должен доказать прогон `locked`

Это ядро приёмки. Набор строго фиксирован: **400 пар — 100 настоящих совпадений
и 300 «трудных» несовпадений**. Пройти нужно все гейты сразу
(`backend/src/marko/comparability_acceptance_cli.py:2092-2188`):

| Гейт | Требование | Смысл |
|---|---|---|
| `locked_true_matches` / `locked_hard_negatives` | ровно 100 / ровно 300 | размер набора нельзя подогнать |
| `false_matches` | ноль | ни одного ложного «это тот же товар» |
| `false_match_upper_95` | верхняя граница 95% < 0.01 | нуля ошибок мало, нужен доверительный интервал |
| `false_not_matches` | ноль | ни одного ложного «это разные товары» |
| `automatic_match_recall` | ≥ 0.70 | автомат должен узнавать большинство совпадений |
| `automatic_decision_coverage` | ≥ 0.75 | не «воздерживаться» на четверти набора |
| `pricing_eligible_sample` / `pricing_ineligible_sample` | ≥ 50 каждой | в наборе есть и допускаемые к цене, и нет |
| `unsafe_admitted` | ноль | ни одного небезопасного допуска |
| `pricing_eligible_admission_rate` | ≥ 0.70 | допуск к цене работает, а не блокирует всё |
| `owned_store_exclusion` | 100% и знаменатель > 0 | собственные магазины исключены, и это проверено на реальных случаях |
| `seller_deduplication` | 100% и знаменатель > 0 | дубли продавцов схлопнуты |
| `provider_terminal_rate` | ≥ 0.98 | провайдер отвечал стабильно |
| `provider_budget_exhausted` | ноль | прогон не оборвался по бюджету |
| `candidate_terminal_accounting` | совпадает с размером набора | ни одна пара не потерялась |

Отдельно нужен прогон `shadow`: **ровно 200 товаров**, все кандидаты
размечены, ноль расхождений с режимом «выключено», та же стабильность
провайдера.

Обратите внимание на два гейта с формулировкой «знаменатель > 0»: набор обязан
содержать реальные случаи собственного магазина и дублей продавцов. Их нельзя
обойти, собрав «удобный» набор.

## 5. Порядок работ

Все команды — подкоманды одного CLI:
`python -m marko.comparability_acceptance_cli <команда>`.

**Шаг 1. Заморозить базовую линию.** `freeze --root … --model … --reasoning-effort …`
фиксирует состояние кода и настроек модели. Всё дальнейшее привязано к этому
снимку.

**Шаг 2. Собрать набор для разметки.** `prepare-locked-review-set` с исходными
CSV, обязательным `--selection-seed` (воспроизводимость выборки) и исключением
уже использованных отладочных наборов. На выходе — CSV и HTML-форма для
проверяющего.

**Шаг 3. Разметка двумя независимыми людьми.** Каждый импортирует свои метки:
`import-locked-review-csv --reviewer-id … --reviewer-role … --attest-independent`.
Это самый долгий шаг: 400 пар автозапчастей, где «трудные несовпадения» —
детали, похожие внешне, но не взаимозаменяемые. Нужен человек, разбирающийся в
предмете; вдвоём это несколько рабочих дней.

**Шаг 4. Проверить согласие проверяющих.** `evaluate-reviewer-agreement` требует
пересечения минимум **41 пара** и согласия по идентичности не ниже 0.95
(каппа 0.85), по допуску к цене — 0.90 (каппа 0.80). Если люди системно
расходятся, разметку придётся переделывать: это защита от «проставил галочки
не глядя».

**Шаг 5. Зафиксировать истину.** `validate-locked-review-set --require-complete`,
затем `finalize-locked-truth --selection-seed …`.

**Шаг 6. Прогнать приёмку.** Получить предсказания системы на этом наборе
(**платный режим LLM-проверки обязателен** — гейты требуют, чтобы провайдер
реально отвечал, `provider_requests > 0`), затем
`evaluate --truth … --predictions … --profile locked` и то же самое для
`--profile shadow` на 200 товарах, плюс `verify-shadow-parity`.

**Шаг 7. Собрать артефакт и включить среду.**
`build-activation-artifact --locked-result … --shadow-result … --runtime-identity …
--product-owner-id … --risk-owner-id … --approved-at … --output …`,
посчитать `sha256` файла, прописать путь и хеш в `.env`, выставить
`ENVIRONMENT=production` вместе с хостами, CORS и `DEBUG=false`.

Бюджет платных вызовов заранее считается подкомандой
`budget --products N --pilot-p95-cost-usd X` — гадать не нужно.

## 6. Что обнуляет артефакт

Это неочевидно и стоит запомнить: артефакт привязан к отпечатку среды. Он
перестаёт действовать, как только меняется **версия промпта, модель или её
настройки** — приложение сверяет отпечаток при каждом старте и вернёт
`RUNTIME_IDENTITY_MISMATCH`.

Практический вывод: приёмку имеет смысл проводить **после** того, как правки
логики сопоставления устоялись. Если провести её сейчас, а затем поправить
лексикон или промпт (а такие правки всплывают на каждом прогоне — за последние
дни их было девять), артефакт придётся выпускать заново вместе с новым платным
прогоном.

## 7. Что мы отдаём сейчас и почему это безопасно

Сдача идёт в `development`. Разница ровно одна: основанием для выпуска цены
служит решение владельца, а не измеренная на 400 парах точность.

Что при этом **не** ослаблено:

- цены никуда не публикуются — ни на Prom, ни автоматически; это отдельный
  запрет, от среды не зависящий, и в интерфейсе он написан прямо на экране;
- все детерминированные гейты сопоставимости работают в полную силу — именно
  они отсеяли лишних продавцов в проверочном прогоне;
- каждая рекомендация воспроизводима: кнопка «Проверить replay» пересчитывает
  её заново и сравнивает с сохранённой;
- расчёт по умолчанию идёт в бесплатном режиме, без обращений к платной модели.

Продакшн — это следующая веха после сдачи, и упирается она не в код, а в
разметку 400 пар. Ориентировочно: несколько рабочих дней двух человек,
разбирающихся в автозапчастях, плюс один платный приёмочный прогон.
