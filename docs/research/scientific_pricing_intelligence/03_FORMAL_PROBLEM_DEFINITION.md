| `δ_i ∈ [0.02, 0.05]` | целевой дисконт | `minimum_discount`/`maximum_discount` `raise_policy.yaml:29-30` |

**Первое расхождение с §6.** Модель §6.2 требует `q_ij` — вероятность. Текущая
система вероятностей не производит вообще. Она производит трёхзначный вердикт
из логических правил. Значит порог `τ` выбирать не из чего, калибровать нечего,
а ROC/PR-кривую построить нельзя — у решения нет непрерывного скора.

Это не мелочь оформления. Это означает, что **λ = C_FP/C_FN = 3, полученное от
владельца 31.07, сегодня не к чему приложить**: `argmin_t [3·FP(t) + FN(t)]`
требует семейства решений, параметризованного `t`, а его нет.

## 2. Selective classification: что уже есть и чего не хватает

Архитектура с отказом от решения **уже реализована**, и это сильная сторона
проекта. Соответствие §6.2:

| §6.2 | Код | Строка |
|---|---|---|
| `Ŷ = 0` при `h = 1` | `conflict_dimensions ≠ ∅ → REJECT` | `comparability.py:311-321` |
| `Ŷ = ⊥` иначе | `failed ≠ ∅ → MANUAL_REVIEW` | `comparability.py:322-323` |
| `Ŷ = 1` при пороге и покрытии | `не failed → PASS`, `ELIGIBLE_VERIFIED` | `comparability.py:324-326` |
| `coverage(e) ≥ m` | `hard_required` по правилу категории | `comparability.py:256-266` |

Чего нет:

1. **Нет `q`.** `Ŷ = 1` достигается выполнением булевых условий, а не
   превышением порога вероятности.
2. **Порог `τ` не выбран, а неявно равен «все hard-поля MATCH»** — то есть
   максимально консервативен по конструкции.
3. **`coverage` определён по категориям, покрывающим 2 категории из 94**
   (см. 01_REPO_GROUND_TRUTH §7.5): практически всегда
   `hard_required = {oe_reference, condition}`.
4. **LLM-уверенность 0…1 сохраняется, но не калибрована.** §6.2 запрещает
   считать её вероятностью до эмпирической калибровки на независимой
   размеченной выборке; такой выборки нет.

### 2.1. Асимметрия, которой в коде нет

§6.3 требует различать цену false accept и false reject. Текущие ворота
трактуют **любое** противоречие одинаково — `REJECT` — независимо от того,
входит размерность в `hard_required` или лишь в `conditional`
(`comparability.py:260-262`, `:311-321`; исполнено, `probe_gate.py` раздел D).

Практически: `engine = CONFLICT` при правиле `generic_unknown`, где `engine`
необязателен, даёт `REJECT`. А `categorical_dimension` сравнивает строки
точным равенством после casefold (`comparability.py:589-608`), поэтому
`'1.9 TDI'` против `'1,9 TDI'` — это CONFLICT.

Формально: решающее правило сейчас

```text
Ŷ = 0   ⟺   ∃ d ∉ INFORMATIONAL :  state(d) = CONFLICT
```

то есть дизъюнкция по 12 размерностям. При независимых ошибках нормализации с
вероятностью η на размерность, вероятность ложного отказа

```text
P(ложный REJECT) = 1 − (1 − η)¹²
```

При η = 1 % это 11.4 %, при η = 3 % — 30.6 %. Это верхняя оценка: реально
большинство размерностей UNKNOWN (парсер их не заполняет), а UNKNOWN не
отвергает. Но она показывает направление: **каждая дополнительно заполняемая
размерность без нормализации увеличивает ложные отказы**, а не уменьшает их.
Улучшение парсинга без улучшения сравнения ухудшит recall.

## 3. Функция потерь: процедура оценки, а не назначенные числа

§6.3:

```text
L = c_FA·1[Ŷ=1,Y=0] + c_FR·1[Ŷ=0,Y=1] + c_A·1[Ŷ=⊥] + c_CR·pricing_impact
```

§6.3 прямо запрещает задавать коэффициенты произвольно. Ниже — процедура их
оценки в единицах, которые заказчик может назвать, и анализ чувствительности.

### 3.1. Приведение к наблюдаемым величинам

Все четыре слагаемых сводятся к гривнам и минутам:

| Коэффициент | Наблюдаемая единица | Как измерить без экспертной оценки |
|---|---|---|
| `c_FA` | UAH недополученной маржи на позицию | \|r_i − r_i^correct\| × ожидаемый месячный объём продаж позиции; `r_i^correct` берётся из ручной коррекции заказчика |
| `c_FR` | UAH упущенной корректировки | \|a_i − r_i^correct\| × объём, для позиций, где отказ скрыл верную рекомендацию |
| `c_A` | минуты | замер времени одного разбора в UI × ставка |
| `c_CR` | UAH | уже входит в `c_FA` через величину ценовой ошибки; отдельным слагаемым нужен только если ошибка нелинейна по величине |

Существенно: `c_FA` **не константа**. Ложное сопоставление с ценой на 3 %
ниже верной и ложное сопоставление с ценой в три раза ниже — разные события.
Поэтому корректная форма не индикаторная, а

```text
L_FA(i) = w(|Δp_i|) · v_i
```

где `Δp` — величина ценовой ошибки, `v_i` — объём. Индикаторная форма §6.3 —
частный случай при `w = const`, и она систематически недооценивает редкие
катастрофические ошибки, которые как раз и порождает минимум с breakdown point
нуль.

### 3.2. Процедура оценки

1. Взять уже существующий поток ручных решений заказчика (§2.7 контракта:
   подтверждение / отклонение / коррекция). Это единственный источник, который
   уже накапливается.
2. Для каждой коррекции записать `(a_i, r_i, r_i^correct, категория, |Δp|)`.
3. `c_FA` и `c_FR` оценивать как средние по этим коррекциям, **раздельно по
   диапазонам |Δp|** — не одним числом.
4. `c_A` замерить прямым хронометражом на 30 разборах.
5. Отношение `λ = c_FA / c_FR` вывести из этих оценок, а **не назначать**.
   Названное владельцем 31.07 значение `λ = 3` использовать как априорную
   гипотезу, подлежащую проверке, а не как измеренный факт.

### 3.3. Анализ чувствительности

Порог, минимизирующий `λ·FP + FN`, устойчив к λ настолько, насколько плоска
PR-кривая вблизи оптимума. Пока кривой нет (§2, нет `q`), sensitivity analysis
невыполним. Порядок работ поэтому жёсткий:

```text
непрерывный скор  →  размеченная выборка  →  PR-кривая  →  оценка λ  →  порог
```

Пропуск любого шага делает следующий недоказуемым. Сегодня не сделан ни один.

## 4. Нормативная ценовая формула и её уязвимость

### 4.1. Что реализовано

```text
E_i = { j : Ŷ_ij = 1, свежесть, продавец ∉ наши, доступность }
p*_i = min_{j ∈ E_i} p^norm_ij
r_i  = RoundDown_1UAH( p*_i · (1 − δ_i) ),  δ_i = 0.02
```

`δ = 0.02` — верхняя граница полосы, то есть **наименее агрессивный срез**
(`market_collection.py:192`, `raise_policy.py:636-637`). Полоса 0.95…0.98
показывается целиком.

Формула соответствует §2.6 контракта и не меняется в этой работе.

### 4.2. Насколько уязвим простой минимум — посчитано

Минимум имеет breakdown point 0; это признано в самом коде
(`raise_policy.py:531-536`). Формализуем.

Пусть каждое предложение из `E_i` независимо оказывается загрязнённым
(ложно-сопоставимым либо ценой-заглушкой) с вероятностью ε, и пусть
загрязнитель, если он присутствует, почти наверняка дешевейший — что и есть
типичный случай, поскольку обе причины загрязнения дают заниженную цену. Тогда

```text
P(минимум задан загрязнением) = 1 − (1 − ε)ⁿ
```

Вычислено (`formal_math.py`, раздел A):

| Сколько предложений в базе | ε=1 % | ε=2 % | ε=5 % | ε=10 % |
|---|---:|---:|---:|---:|
| медиана текстового поиска ≈ 1.5 | 1.5 % | 3.0 % | 7.4 % | 14.6 % |
| `min_evidence = 3` | 3.0 % | 5.9 % | 14.3 % | 27.1 % |
| медиана `kept` на странице кода = 7 | 6.8 % | 13.2 % | **30.2 %** | 52.2 % |
| потолок `max_sellers = 10` | 9.6 % | 18.3 % | 40.1 % | 65.1 % |
| если потолок снять, ≈ 62 | 46.4 % | 71.4 % | **95.8 %** | 99.9 % |

**Главный вывод этого раздела, и он контринтуитивен.**

Повышение полноты поиска **увеличивает** риск ошибки, пока ориентиром служит
минимум. Переход со текстового поиска на страницу кода поднял `kept` с 41 до
223 на 28 позициях (01_REPO_GROUND_TRUTH §7.1) — то есть примерно с 1.5 до 7 на
позицию. При ε = 5 % это подняло вероятность, что рекомендация задана мусорным
предложением, с **7.4 % до 30.2 % — в 4.1 раза**.

Отсюда два следствия:

1. Потолок `max_sellers = 10` сегодня работает как **случайная защита**. Он
   введён как ограничение стоимости, но фактически удерживает экспозицию
   минимума на 40 % вместо 96 %. Снимать его без замены оценки ориентира
   нельзя — это выглядит как улучшение охвата и является ухудшением качества.
2. Работа над recall и работа над робастностью ориентира **не независимы**.
   Их нельзя приоритизировать по отдельности.

ε сегодня неизвестно — его оценка требует размеченного набора и является
задачей PHASE 4.

### 4.3. Вопросы §6.4, на которые формализация даёт ответ

**Когда 2 %, а когда 5 %.** Сейчас всегда 2 %. Соблазн — увеличивать δ при
высокой неопределённости. Это ошибка: если `p*` занижен загрязнением, любое
увеличение δ усугубляет ошибку, а не страхует от неё. Неопределённость
относительно `p*` должна поглощаться выбором более робастной оценки `p*` либо
отказом от рекомендации, а не величиной δ. **δ — параметр позиционирования
(бизнес), а не статистический.** Рекомендация: δ оставить фиксированным,
уверенность выражать отдельным полем и правом на отказ.

**Минимальный значимый шаг.** `psychological_step = 1 UAH` для budget_floor
против 10 UAH у legacy (`raise_policy.yaml:28, 62`). Обосновано: на дешёвых
позициях шаг 10 UAH выбрасывает результат за коридор 2–5 %. Проверяемо: при
цене 200 UAH коридор шириной 3 % = 6 UAH, то есть меньше legacy-шага.

**Валютное округление, доставка, НДС, доступность, упаковка.** `package_quantity`
— размерность ворот; доставка и НДС в `p^norm` **не входят**, и это
незадокументированное допущение: сравниваются цены карточек. Если у продавцов
разная политика доставки, `p^norm` систематически смещена. Не измерено.

**Зависимость продавцов и устаревшие наблюдения** — §5 ниже.

## 5. Независимость наблюдений: формализация проблемы нулевого разброса

### 5.1. Что делает код

```text
robust_cv = IQR / p50                        raise_policy.py:276
HIGH   ⟺  n ≥ 4  и  robust_cv < 0.15         raise_policy.py:328-332
MEDIUM ⟺  n ≥ 3  и  robust_cv < 0.35         raise_policy.py:333-337
```

### 5.2. Почему это ошибка категории

`IQR/p50` — мера **разброса оценки**. Она отвечает на вопрос «насколько
согласованы наблюдения». Она ничего не знает о том, **независимы ли они**.

Совпадение цены у нескольких формально разных продавцов — сильнейший доступный
признак зависимости: один поставщик, дропшиппинг, зеркальная выгрузка прайса.
При зависимости `IQR → 0`, следовательно `robust_cv → 0`, следовательно
`HIGH`.

Исполнено на реальных данных (`probe_ties.py`):

| Когорта | n | IQR | robust_cv | грейд |
|---|---:|---:|---:|---|
| 4 **разных** продавца по 400 UAH | 4 | 0.00 | 0 | **HIGH** |
| 4 продавца: 400, 400, 400, 401 | 4 | 0.25 | 0.000625 | **HIGH** |
| 4 продавца, честный разброс 369…914 | 4 | 316.25 | 0.575 | **LOW** |

То есть система уверена ровно там, где данных меньше всего, и не уверена там,
где рынок работает нормально.

Совпадения — не редкость. На 29 реальных предложениях живого парса:

| Величина | Значение |
|---|---|
| предложений в совпадающих ценах | **17 из 29 (59 %)** |
| различных цен | 18 при 29 предложениях |
| 400 UAH | 4 предложения, **4 разных продавца** |
| 1 466 UAH | 4 предложения, 3 разных продавца |

### 5.3. Формальная поправка

Ввести эффективный размер выборки через design effect:

```text
n_eff = n / (1 + (n̄ − 1)·ρ)
```

где `n̄` — средний размер кластера зависимых предложений, `ρ` — внутрикластерная
корреляция. Кластеризация по точному совпадению цены даёт **верхнюю границу**
зависимости (`ρ = 1`), кластеризация её отсутствие — нижнюю (`ρ = 0`).

Вычислено на тех же данных (`formal_math.py`, раздел E):

| Величина | Значение |
|---|---|
| наблюдений `n` | 29 |
| кластеров по точной цене | 18 |
| средний размер кластера `n̄` | 1.61 |
| `n_eff` при `ρ = 1` | **18** |
| `n_eff` при `ρ = 0` | 29 |

Что это делает с порогом `min_evidence = 3`: цены 400, 914 и 1 466 UAH
представлены 4, 3 и 4 предложениями, каждая из которых при `ρ = 1` — **одно**
независимое наблюдение. Позиция, формально набравшая 4 продавца и получившая
`HIGH`, может опираться на одно.

**Честная оговорка.** Точное совпадение цены не доказывает зависимости: два
продавца могут независимо назначить круглые 400 UAH. Поэтому `ρ = 1` —
консервативная верхняя граница поправки, а не измеренная величина. Измерение
требует внешнего признака связи продавцов (общий поставщик, идентичные
описания, идентичные фото), и это отдельная задача.

Существенно: сам проект уже знает эту проблему в другой форме — у KEMP четыре
собственные витрины на Prom с идентичными карточками
(`docs/HANDOFF_CODEX_2026-07-31.md`), и они решаются исключением
`excluded_seller_ids`. Тот же механизм у **чужих** продавцов не обнаруживается
никак.

## 6. Robust market reference: пространство альтернатив

§6.5 требует не заменять минимум, а измерить, как часто он задан ошибочным
предложением. Кандидаты для сравнительного эксперимента с их breakdown point:

| Оценка | Breakdown point | Сохраняет ли смысл «самый дешёвый» | Готовность данных |
|---|---|---|---|
| `min` — текущая | **0** | да, буквально | есть |
| `min` после детерминированных фильтров загрязнения | 0, но ε ниже | да | частично: фильтры есть, эффект не измерен |
| 2-я порядковая статистика | `1/n` | почти | есть |
| k-я порядковая статистика (trimmed min) | `k/n` | ослабляет | есть |
| нижний квантиль `q` | `q` | ослабляет заметно | есть |
| `corroborated_floor(k продавцов)` | `(k−1)/n` | сохраняет при малом k | **реализовано**, `raise_policy.py:602-620`, выключено |
| weighted lower quantile по независимости продавцов | зависит от весов | да | нужен признак зависимости |
| M-оценки, empirical Bayes, mixture «реальные + загрязнение» | высокий | косвенно | **нет данных**: нужна разметка |
| posterior lower credible price | высокий | да, с интервалом | нет данных |

**Ключевое наблюдение.** `floor_corroboration_sellers` уже реализован и
выключен решением владельца (`raise_policy.yaml:44-47`). Значение 2 даёт
breakdown point `1/n` вместо нуля — то есть переход от «одно плохое
предложение решает всё» к «нужны два». Это **самое дешёвое из доступных
улучшений робастности**: код есть, тесты есть, требуется только измерение
эффекта и решение владельца.

Требуемое измерение формулируется точно: на размеченном наборе посчитать долю
позиций, где минимум задан предложением с меткой `NOT_COMPARABLE`,
`INSUFFICIENT_DATA` или ценой-заглушкой, — раздельно при
`floor_corroboration_sellers = 1` и `= 2`, с интервалом Уилсона.

## 7. Планирование объёма выборки

### 7.1. Precision положительного класса

Знаменатель precision — только пары, где система предсказала «сопоставимо».
Интервал Уилсона при `k = round(0.8·n)` успехов (`formal_math.py`, раздел D).
Уточнение после самоаудита: при `n = 11` целое `k = 9` даёт `p̂ = 0.818`, а не
ровно 0.800; при точном `p̂ = 0.800` полуширина составила бы 21.8 п.п. вместо
21.3. Различие ниже практической значимости и вывода не меняет.

| n предсказанных «сопоставимо» | 95 % интервал | полуширина |
|---:|---|---:|
| **11** — столько в текущем золотом наборе | [0.523, 0.949] | **±21.3 п.п.** |
| 20 | [0.584, 0.919] | ±16.8 п.п. |
| 30 | [0.627, 0.905] | ±13.9 п.п. |
| 40 | [0.652, 0.895] | ±12.1 п.п. |
| 60 | [0.682, 0.882] | **±10.0 п.п.** |
| 97 | [0.714, 0.871] | ±7.8 п.п. |
| 120 | [0.720, 0.862] | ±7.1 п.п. |

Порог «не менее 97 размеченных пар» относится к **размеру всего набора**, а не
к знаменателю precision. Для цели `e = 0.10` по precision нужно около **60
предсказанных-положительных** пар. В текущем наборе из 120 их **11**.

### 7.2. Critical false accept rate

Для редкого события интервал Уилсона при `k = 0` не вырождается, в отличие от
нормального. При `k = 0`, `n = 97`, `z = 1.96` верхняя граница ≈ 3.8 %. То есть
даже безупречная разметка 97 пар не позволит утверждать, что доля критических
ложных допусков ниже ≈ 4 %. Если требование строже, объём нужно планировать от
требования, а не от удобства.

### 7.3. Кластеризация при подсчёте интервалов

Пары не независимы: несколько кандидатов принадлежат одному товару `u_i` и
одному продавцу. Обычный биномиальный интервал занизит ширину. Требуется
**cluster bootstrap** с кластером по `product/OE`, а не по строке. Это же
относится к разбиению train/dev/test — по `product/OE`, иначе тот же товар
попадёт в обе стороны и даст утечку.

## 9. Что этот этап установил

1. Selective classification **уже есть** и реализована консервативно — это
   сильная сторона.
2. Но у решения **нет непрерывного скора**, поэтому порог, калибровка,
   PR-кривая и применение λ невозможны в принципе, а не по недостатку данных.
3. Правило отказа — дизъюнкция по 12 размерностям при строковом сравнении;
   улучшение парсинга без нормализации **ухудшит** recall.
4. Уязвимость минимума посчитана: рост полноты поиска в 4.7 раза поднял
   экспозицию минимума в 4.1 раза. Потолок `max_sellers` случайно защищает.
5. Грейд уверенности смешивает согласие наблюдений с их независимостью;
   59 % реальных предложений стоят на совпадающих ценах.
6. Самое дешёвое доступное улучшение робастности —
   `floor_corroboration_sellers = 2`: код готов, нужен замер и решение.
7. Для precision с точностью ±10 п.п. нужно ≈ 60 предсказанных-положительных
   пар; сейчас 11.
