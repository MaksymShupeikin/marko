## ЧАСТЬ I — РАМКА ОЦЕНКИ

### 1. Метрики генерации кандидатов (§11.1)

| Метрика | Определение | Знаменатель | Измеримо сейчас |
|---|---|---|---|
| `coverage_listing` | забрано предложений / `page.total` листинга | листинг | **нет** — `page.total` отбрасывается (M-06) |
| `candidates_scanned` | просмотрено кандидатов | позиция | да |
| `offers_after_dedup` | дешевейших на продавца | позиция | да |
| `offers_after_cap` | после `max_sellers` | позиция | да |
| `cap_binding_rate` | доля позиций, упёршихся в потолок | позиции | да — **измерено: 62 %** |
| `kept_rate` | `kept / offers` | позиция | да |
| `zero_market_rate` | доля позиций с `kept = 0` | позиции | да — измерено: 15 из 28 на пути `SEARCH` |
| `recall@source` | найденные сопоставимые / все существующие | **неизвестен** | нет — требует разметки |

**Ограничение, которое нельзя обойти.** Настоящий recall неизмерим: знаменатель
«все существующие сопоставимые предложения на Prom» недоступен. Измеримы только
относительные величины — сравнение источников между собой на одних позициях.
Любое утверждение вида «полнота 80 %» будет неправдой.

### 2. Метрики сопоставимости (§11.2)

| Метрика | Формула | Знаменатель | Блокер |
|---|---|---|---|
| precision положительного класса | TP/(TP+FP) | **принятые пары** | DB-02: принятых пар в наборе ноль |
| recall | TP/(TP+FN) | истинно сопоставимые | DB-01 |
| доля ложных отказов | FN/(FN+TN) | **отклонённые пары** | DB-01 — измерима текущим набором |
| critical false accept rate | доля принятых с hard contradiction | принятые | DB-02 |
| abstention rate | доля `MANUAL_REVIEW` | все пары | **измерима сейчас** |
| доля отказов по причинам | по `reason_codes` | отказы | **измерима сейчас** |

Все доли сообщаются **только с интервалом Уилсона и размером выборки**.
Нормальный интервал не применяется: при `k = 0` он вырождается в `[0,0]` и
создаёт ложную уверенность.

### 3. Метрики калибровки (§11.3)

`ECE`, `MCE`, надёжностная диаграмма, Brier score — все требуют
размеченной выборки с сохранённым скором. Сегодня неприменимы: скор существует
только в LLM-контуре, а он в режиме `off`.

Отдельно: **разделять калибровку по `EXACT` и `ACCEPTABLE_ANALOGUE`**, как
требует `docs/LLM_COMPARABILITY_2026-07-31.md:78-79`. Общая калибровка скроет,
что для аналогов уверенность может быть систематически иной.

### 4. Ценовые метрики (§11.4)

| Метрика | Определение | Измеримо сейчас |
|---|---|---|
| `floor_rests_on_one_seller_rate` | доля позиций, где минимум держит один продавец | **да, уже флагом** |
| `contaminated_floor_rate` | доля позиций, где минимум задан парой с меткой `NOT_COMPARABLE` | нет — DB-01 |
| `band_width_uah` | ширина полосы 95–98 % | да |
| `action_distribution` | RAISE / LOWER / HOLD / MANUAL_REVIEW | да |
| `recommendation_delta` | \|r − a\| и в процентах | да |
| `deep_cut_rate` | доля снижений глубже 50 % | да — измерялось: 109 из 193 при сыром минимуме |
| `n_eff_ratio` | `n_eff / n` по совпадению цен | **да, новая** |

### 5. Человеческий фактор (§11.5)

| Метрика | Как измерить |
|---|---|
| время одного разбора | хронометраж 30 разборов в UI |
| доля подтверждений оператора | из append-only feedback |
| доля коррекций | оттуда же |
| величина коррекции \|r − r_correct\| | оттуда же |
| очередь на разбор | `MANUAL_REVIEW` на прогон |

Последнее критично: `apply_comparability_activation_gate` переводит **все**
`automatic_eligible` в `MANUAL_REVIEW`, пока активация не подтверждена. Значит
очередь равна числу позиций с рекомендацией, и её размер — это ограничение
пропускной способности человека, а не системы.

### 6. Статистическая корректность (§11.6)

Обязательные требования ко всем числам в этой программе:

1. **Интервалы Уилсона** для долей; Clopper–Pearson при `k = 0` или `k = n`.
2. **Cluster bootstrap** с кластером по `our_oe`: пары не независимы, до 3 на
   товар.
3. **Разбиение по `product/OE`**, не по строкам — иначе утечка.
4. **Поправка на множественные сравнения** при проверке более одной гипотезы
   на одном наборе (Holm или Benjamini–Hochberg, выбрать до анализа).
5. **Размер выборки объявляется до эксперимента**, не подбирается по
   результату.
6. Различать **статистическую** и **практическую** значимость: разница в 1 п.п.
   precision может быть значима и бесполезна.

## ЧАСТЬ II — ПРОГРАММА ЭКСПЕРИМЕНТОВ

Пять первых полностью специфицированы, как требует §19.

### EXP-00 — Baseline текущей системы

**Вопрос.** Что система делает сегодня, в числах, до любых изменений.

**Данные.** Существующие артефакты + прогон на текущем каталоге без сети
(replay).

**Измеряется.** Все метрики §1, §4, §5, для которых написано «измеримо
сейчас». Раздельно по `source ∈ {PROM_OE_PAGE, SEARCH}`.

**Критерий.** Эксперимент не имеет критерия прохождения — он задаёт точку
отсчёта. Его результат становится знаменателем всех последующих.

**Стоп-условие.** Если `source` не сохранён в части наблюдений, разделение
невозможно — тогда EXP-00 сначала чинит инструментирование.

**Статус:** `PARTIAL` — часть величин уже измерена в 01_REPO_GROUND_TRUTH.

---

### EXP-01 — Идентичность источника доходит до доказательств (M-02)

**Гипотеза.** Отдельная размерность `marketplace_grouping` поднимет долю
`automatic_eligible` на пути `PROM_OE_PAGE`, не увеличив ложные допуски.

**Обоснование.** Измерено (01_REPO_GROUND_TRUTH §7.2): кандидат со страницы
кода без номера в заголовке получает `oe_reference = UNKNOWN` и
`MANUAL_REVIEW` с `MANUAL_MISSING_OE_PROVENANCE`.

**План.**
1. Зафиксировать `automatic_eligible_rate` на пути `PROM_OE_PAGE` (EXP-00).
2. Добавить размерность, не удаляя `oe_reference`.
3. Пересчитать на том же наборе наблюдений (replay, без сети).
4. Разметить 60 случайных пар, ставших `PASS`, — иначе рост доли ничего не
   доказывает.

**Критерий прохождения, заданный заранее.**
- `automatic_eligible_rate` вырос статистически значимо (Уилсон, непересечение
  интервалов), **И**
- доля ложных допусков среди новых `PASS` не выше 5 % с верхней границей
  интервала не выше 10 %.

**Критерий провала.** Верхняя граница ложных допусков выше 10 % — метод
отклоняется независимо от прироста охвата.

**Стоп-гейт.** Без разметки 60 пар эксперимент завершается статусом
`BLOCKED_LABELS`, а не `PASS`.

**Риск.** Изменение состава размерностей меняет `COMPARABILITY_POLICY_HASH` и
инвалидирует сохранённые доказательства. Версионировать политику.

### EXP-02 — Непрерывный вес против булевой дизъюнкции (M-01)

**Гипотеза.** Вес Fellegi–Sunter, параметры которого оценены EM по
неразмеченным парам, воспроизводит текущие решения и при этом даёт монотонный
скор, пригодный для порога и conformal.

**План.**
1. Собрать матрицу состояний 13 размерностей по всем сохранённым наблюдениям.
2. Оценить `m_i = P(совпало | пара сопоставима)` и
   `u_i = P(совпало | не сопоставима)` EM-алгоритмом.
3. Вычислить вес `w = Σ log(m_i/u_i)` по совпавшим и `Σ log((1−m_i)/(1−u_i))`
   по несовпавшим.
4. Сравнить порядок, задаваемый весом, с текущими вердиктами.
5. На размеченной подвыборке построить PR-кривую.

**Критерий прохождения.**
- Согласие с текущими `REJECT`/`PASS` не ниже 95 % при подобранных порогах, **И**
- PR-AUC на размеченной подвыборке значимо выше случайного (нижняя граница
  bootstrap-интервала выше 0.5 для сбалансированной задачи).

**Критерий провала.** EM не сходится либо `m_i ≈ u_i` для всех размерностей —
это будет означать, что при 98 % UNKNOWN данных для оценки просто нет. Тогда
метод переводится в `AFTER_DATA`.

**Почему это важнее прочего.** Без непрерывного скора невозможны EXP-09
(conformal), EXP-11 (порог по λ) и вся калибровка. Это узкое место всей
программы.

### EXP-03 — Нормализация атрибутов (M-03)

**Гипотеза.** Нормализация единиц, разделителей и синонимов до
`categorical_dimension` снижает ложные отказы, не повышая ложные допуски.

**Обоснование.** Измерено: `'1.9 TDI'` против `'1,9 TDI'` даёт `CONFLICT`, а
любой `CONFLICT` в неинформационной размерности даёт `REJECT`.

**План.**
1. Посчитать на сохранённых наблюдениях частоту `CONFLICT` по каждой из 12
   неинформационных размерностей.
2. Для трёх самых частых построить нормализатор.
3. Пересчитать; измерить изменение доли `REJECT`.
4. Разметить 40 пар, у которых вердикт сменился с `REJECT` на не-`REJECT`.

**Критерий прохождения.**
- Доля `REJECT` по орфографическим причинам упала значимо, **И**
- среди 40 пар со сменившимся вердиктом доля действительно несопоставимых не
  выше 10 %.

**Критерий провала.** Больше 10 % — нормализация склеивает разные значения.

### EXP-04 — Расширение словаря применимости (M-07)

**Гипотеза.** Расширение словаря повысит долю подтверждённой применимости, не
увеличив ложные отказы.

**Обоснование и предупреждение.** Измерено (04_DATA_READINESS §4): марка
распознаётся у 48 % наших товаров, модель — у **2 %**. Гейт при
нераспознанной модели возвращает `APPLICABILITY_UNKNOWN` без отказа, но при
непересекающихся марках — отвергает. Словарь слишком мал, чтобы подтверждать,
и достаточно велик, чтобы отвергать. **Расширение без замера ложных отказов
ухудшит recall.**

**План.**
1. Зафиксировать текущие доли распознавания марки и модели.
2. Расширить словарь до марок и моделей, фактически встречающихся в каталоге.
3. Пересчитать; отдельно измерить прирост `BRAND_MISMATCH` и прирост
   подтверждённой применимости.
4. Разметить 40 пар, ставших `BRAND_MISMATCH` после расширения.

**Критерий прохождения.**
- Доля подтверждённой применимости выросла, **И**
- доля новых `BRAND_MISMATCH`, оказавшихся ложными, не выше 10 %.

**Критерий провала.** Новых ложных отказов больше, чем новых подтверждений, —
расширение откатывается.

---

### EXP-05 — Зависимость продавцов и эффективный размер выборки (M-05)

**Гипотеза.** Значимая доля позиций имеет `n_eff` существенно ниже `n`, и
грейд `HIGH` систематически выдаётся когортам с зависимыми наблюдениями.

**Обоснование.** Измерено на реальном парсе: 59 % предложений стоят на
совпадающих ценах; 4 разных продавца по 400 UAH дают `HIGH`, честный разброс
369–914 — `LOW`.

**План.**
1. По всем сохранённым когортам посчитать: число совпадающих цен, размер
   кластеров, `n_eff` при `ρ = 1`.
2. Добавить внешние признаки связи: совпадение описания, совпадение фото по
   хэшу, совпадение SKU.
3. Оценить `ρ` по доле кластеров, подтверждённых внешним признаком.
4. Пересчитать грейд на `n_eff`; измерить, сколько `HIGH` становится `MEDIUM`
   или `LOW`.

**Критерий прохождения.**
- `ρ` оценено с интервалом, **И**
- названа доля позиций, у которых грейд менялся бы.

**Критерий провала.** Внешние признаки не находят подтверждения ни для одного
кластера — тогда совпадение цен объясняется округлением, и гипотеза снимается.

**Важно.** Этот эксперимент **ничего не меняет** в грейде. Он только измеряет.
Изменение грейда — отдельное решение владельца.

---

### EXP-06 — Охват листинга и оценка нижнего хвоста (M-06, M-15)

Инструментировать `page.total`; на подвыборке из 20 позиций забрать листинг
целиком; сравнить минимум по префиксу из 90 предложений с минимумом по полному
листингу.

**Критерий прохождения.** Названа доля позиций, где полный минимум ниже
префиксного, и медианная величина расхождения в процентах.

**Ожидаемое следствие.** Если расхождение существенно, вся ценовая политика
опирается на смещённую вверх оценку минимума, и это надо признать явно.

---

### EXP-07 — Латеральная проверка (M-08)

Прогнать `laterality_conflict` по корпусу реальных заголовков; вручную
проверить 50 сработавших пар; посчитать долю ложных срабатываний с интервалом.

**Критерий прохождения.** Доля ложных срабатываний измерена; после замены на
разбор по границам слов она значимо ниже, а доля пропущенных настоящих
конфликтов не выросла.

---

### EXP-08 — Робастность ценового ориентира (M-04, M-16)

Сравнить на одних данных: сырой минимум, минимум при
`floor_corroboration_sellers = 2`, вторую порядковую статистику, минимум после
пометки выбросов.

**Критерий прохождения.** Для каждого варианта названы: число изменившихся
рекомендаций, доля глубоких снижений, доля позиций, где минимум держал один
продавец.

**Стоп-гейт.** Выбор варианта — **решение владельца** (G-6). Эксперимент даёт
числа, не рекомендацию к включению.

---

### EXP-09 — Conformal risk control (M-09)

Требует EXP-02 (скор) и калибровочной выборки. Статус: `BLOCKED_LABELS`.

**Критерий прохождения.** Эмпирическая доля ложных допусков на отложенной
выборке не превышает заявленную. Кластерная версия по `our_oe`.

---

### EXP-10 — Калибровка LLM (M-10)

Требует shadow-прогона с реальным ключом и разрешения владельца на передачу
каталожных данных внешнему сервису (DB-06). Статус: `BLOCKED_POLICY`.

---

### EXP-11 — Выбор порога по λ (M-11)

Требует EXP-02. Порог `argmin(λ·FP + FN)` с анализом чувствительности по λ ∈
[2, 5]. Если оптимальный порог меняется в этом диапазоне существенно — решение
откладывается до измерения λ по процедуре 03_FORMAL §3.2.

---

### EXP-12 — Активное обучение (M-13)

Сравнить ширину интервала при равном числе размеченных пар: активный отбор
против случайного. **Обязательное условие:** не менее 30 % пар в каждой порции
отбираются случайно — иначе усиливается selection bias.

---

### EXP-13 — Иерархическое объединение по категориям (M-14)

Leave-one-category-out: точность предсказания по редкой категории при общем
правиле против частичного объединения.

них ничего не меняет в production — только измеряет.

## 8. Общие стоп-гейты программы

Ни один эксперимент не получает статус `PASS`, если выполняется хотя бы одно:

- доказана только работоспособность кода, но не полезность на рынке;
- нет независимой отложенной выборки;
- критические ложные допуски не измерены;
- результат не воспроизводится;
- улучшение меньше практической значимости, даже если статистически значимо;
- метод требует данных, которых нет;
- доменную величину назначил агент, а не владелец.
