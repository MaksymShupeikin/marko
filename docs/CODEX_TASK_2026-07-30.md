## 6. Как работать

```
Измеряй до и после. «Стало быстрее» без p95 — не результат.
Каждая правка дефекта — с тестом, который падает на прежнем коде.
   Проверь это буквально: откати правку, прогони, верни.
Не трогай продакшн-код «заодно». Отдельная правка — отдельная причина.
Массовый автофикс запрещён: ruff format src, dart fix --apply и подобное
   создают сотни несвязанных изменений. Форматируй только свои файлы поимённо.
После правки backend/src пересобирай воркеры, иначе проверяешь старый код.
Перед миграцией — бэкап. Downgrade обязан работать, проверь на одноразовой БД:
   createdb marko_migtest, upgrade head, downgrade -1, upgrade head, alembic check.
Фоновые сервисы пишут в БД во время работы. Любое число из базы — со снимком
   (таблица, COUNT(*), момент). Два числа из разных моментов не сравнивай.
Не назначай доменные величины: тиры, премии, пороги цены, охват мото.
   Показать, что значение не откалибровано — можно. Выбрать его — нет.
Отчёт: что сделал, что измерил, что не проверил, что осталось сломанным.
   Без футеров и без «в целом успешно».
```
