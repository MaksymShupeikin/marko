**п.2** — `GLOBAL_OWN_PROM_SELLERS` в
`backend/src/marko/services/competitor_prices.py` держит все четыре магазина
(kemp, avtobust, profparts, parts-avto); те же четыре лежат в таблице

решение заказчика.

**п.3** — группировка в `repositories/listings.py`:
`row_number() OVER (PARTITION BY нормализованный SKU ORDER BY price ASC NULLS LAST)`.
Нормализация: убрать всё кроме букв и цифр, верхний регистр, отрезать хвост
`(KEMP)`. Ранжирование стоит **до** фильтров — иначе фильтр по магазину меняет
представителя. Представитель — строка с наименьшей **положительной** ценой.
API отдаёт `group_size` и `siblings`; фронт рисует блок «Ваші магазини»
(`product_details_panel.dart` → `_OwnStoresGuidance`) с советом по каждому
магазину относительно рекомендованной цены.

**п.4** — конвертация НБУ (`_to_uah` → `exchange_rates.uah_rates`), двусторонний
отсев выбросов `_OUTLIER_FACTOR = 8`, нули режут `_drop_implausible` и
`effective_price`. Google-источник ограничен доменами `.ua`
(`_SERP_ALLOWED_TLD`) — польские объявления больше не приезжают.

**п.6** — `_RECOMMENDED_DISCOUNT = Decimal("0.94")`, а
`_RECOMMENDED_DISCOUNT_PERCENT` уходит в `stats` ответа API. Фронт **не** хардкодит

## 2. Сделано сверх списка

- **Поиск по номеру производителя, а не по артикулу магазина.** Три пути
  добычи номеров: колонка `Пошукові_запити` в XLSX-экспорте
  (`parsers/prom_export.py`), атрибуты Apollo на странице товара
  («Код запчастини», «Кросс-номери» → `services/parser_models.py`), и
  одноразовая дозагрузка страницы, когда номеров нет в базе — результат
  пишется в `raw_data` (`set_listing_oem_numbers`). Общий разбор вынесен в
  `parsers/part_numbers.py`; `order_numbers` ставит номер с буквой первым,
  потому что в поиск уходят только первые два термина, а чисто цифровой
  токен — это внутренний артикул, по которому конкурентов не найти.
- **Марка бренда перестала быть якорем.** 86% каталога — KEMP, и подстановка
  своей марки в запрос отравляла подбор. `_market_brand()` вычищает её,
  но **только для сайтов**: avto.pro ищет именно по марке, без неё выдача
  пустая.
- **Удаление магазинов и файла.** Корзинки по ховеру на карточках
  (`frontend/lib/features/products/widgets/stores_strip.dart`), отдельная
  строка «Файли» над магазинами. Удаление файла снимает его с роли основного
  референса поиска. Бэкенд: `count_export_listings_for_store`,
  `delete_export_listings_for_store`.
- **Очередь импорта.** Строгая очередь вместо параллельных загрузок, капсула
  прогресса показывает всю очередь, отменённый импорт исчезает сразу.
- **«File with links»** — одноразово сгенерированный XLSX (лежит у заказчика в
  Downloads), ссылка на товар берётся из kemp, если нет — из любого другого
  магазина. Это **не фича приложения**, кнопки в интерфейсе нет.
- **Ошибка «Failed to fetch» при импорте XLSX** — миграция
  `20260829_0013_repair_exclusion_identity.py`, см. п.5.

## 3. Контракты, которые нельзя менять мимоходом

`backend/src/marko/services/competitor_prices.py`:

```
GLOBAL_OWN_BRANDS   = ("kemp",)
GLOBAL_OWN_DOMAINS  = ("kemp.ua",)
_SERP_ALLOWED_TLD   = ".ua"
_SERP_COVERED_DOMAINS = ("prom.ua", "avto.pro", "exist.ua")
_RECOMMENDED_DISCOUNT = Decimal("0.94")   # процент едет во фронт из stats
_MIN_STATS_CONFIDENCE = 0.7
_ANALOG_CONFIDENCE    = 0.75
_UNVERIFIED_CONFIDENCE = 0.5
_MIN_STATS_SAMPLE     = 3
_OUTLIER_FACTOR       = Decimal("8")
_SUSPICIOUS_LOW_FACTOR = Decimal("2.5")
```

Ключ кеша отчёта — `competitor-prices:v11:{listing_id}:{sha1}`.
**Меняешь форму отчёта — поднимай версию**, иначе старые отчёты будут
приезжать в новый интерфейс. Вердикты фото-проверки кешируются отдельно
под `photo-used:v1:{sha1(url)}` — **меняешь семантику `_PHOTO_SYSTEM`
в `llm_filter.py` — поднимай и эту версию**, иначе недельные вердикты
старого промпта продолжат применяться.

**Фото-проверка Б/У (добавлена 30.08, коммит `983f9be`).** Модель смотрит
на фото самых дешёвых якорных предложений (до 4 на отчёт) и ловит детали
с разборки, о которых продавец молчит в тексте. Файлы:
`services/photo_check.py` (кеш вердиктов по URL), `photo_condition` в
`llm_filter.py`, `_photo_check_offers` в `competitor_prices.py`.
Инварианты: збой vision-вызова ≠ вердикт (предложение нетронуто);
«used» + подозрительно дёшево → отсев, «used» при рыночной цене →
видим со станом «б/у», но вне статистики; фон фото не улика — только
следы эксплуатации на детали. Флаг `COMPETITOR_PHOTO_CHECK_ENABLED`.

## 4. Инварианты багфиксов — не регрессировать

- **Вердикт `unsure` роняет только подозрительно дешёвые предложения.**
  Раньше «стан=невідомо» выбрасывал из статистики вообще всё с Prom и Google.
  Сейчас: если цена ≥ `anchor / _SUSPICIOUS_LOW_FACTOR`, предложение остаётся
  как есть.
- **Б/У ловится машинным флагом, а не текстом.** У avto.pro это
  `data-bu="1"` и `data-is-cardismantling` (`parsers/avtopro/parser.py`,
  `_is_used`). Только 1 из 5 б/ушных строк содержала «б/у» в тексте — на
  текстовом поиске гейт не работал.
- **`_stats_prices` не схлопывает выборку до пустоты.** Если сильных
  совпадений меньше `_MIN_STATS_SAMPLE`, а всего предложений достаточно —
  считаем по всем. Иначе рекомендация выезжала на единственной дорогой цене
  (советовала поднять до 1366 ₴ при живых предложениях по 516 ₴).
- **Группировка ранжирует до фильтров**, представитель — наименьшая
  **положительная** цена, нулевая ценой представителя не становится.
- **`list_stores` отдаёт полный кортеж.** Он резал его до трёх полей, и
  счётчик файлов всегда показывал 0. Юнит-тесты мокали репозиторий и это
  пропустили — проверять живьём.

## 5. Ловушки окружения (важно для параллельной работы)

- **Голова миграций теперь `20260829_0013`.** Коллизия `20260828_0012`
  случилась ровно из-за параллельной работы двух веток: обе создали ревизию
  с одним номером, но разными именами уникального ограничения. Alembic
  считал ревизию применённой и не переигрывал, база оставалась с чужим
  именем, код падал на `ON CONFLICT ON CONSTRAINT
  uq_competitor_seller_exclusion_identity` — у заказчика это выглядело как
  «Failed to fetch» при импорте. Новые ревизии должны иметь
  `down_revision = "20260829_0013"`.
- **У контейнера `backend-test` нет volume mount** — без `--build` он гоняет
  старый код:
  ```
  docker compose -p marko run --rm --build backend-test
  ```
- **Общее имя Docker-проекта `marko`** затирает сборки при параллельной
  работе двух сессий над разными копиями репозитория. Симптом: интерфейс
  показывает поведение чужой ветки.

## 6. Открытые вопросы — без слова заказчика не начинать

1. **Exist.ua как живой источник.** `ExistPriceSource` написан и подключён,
   но на бесплатном тарифе Serper запрос `site:exist.ua` запрещён
   («Query pattern not allowed for free accounts»). Источник аккуратно
   отдаёт статус `skipped` (не `error`) через `_SourceUnavailable`.
   Чтобы заработал — платный тариф Serper либо прямой обход Cloudflare.
2. **Кросс-номера с Exist.ua.** На карточке Exist есть вкладка «Оригінальні
   номери» (Kemp 77644811 → VAG 3B5 827 550 A). Предложены два шага:
   (a) сначала померить настоящий разрыв — сколько позиций остаются
   **только** с внутренним кодом KEMP серии `776…`; это чистая арифметика по
   базе, без единого запроса наружу; (b) если дыра заметная — тянуть номер
   **по требованию**, только когда отчёт по товару не нашёл рынка. Это
   десятки запросов в день вместо тысяч. Решение за заказчиком.
3. **Разброс первого прохода модели.** Один и тот же товар даёт то 3, то 29
   предложений между запусками, рекомендация гуляет между ~485 и 1366 ₴.
   Причина в недетерминизме первого прохода классификации. Лечится либо
   детерминизмом вызова, либо отказом доверять единственному вердикту по
   строке. Задача показана заказчику, **не начата намеренно**.
