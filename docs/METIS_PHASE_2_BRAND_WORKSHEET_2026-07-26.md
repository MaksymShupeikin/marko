## 3. Главное предупреждение: подсказке по цене верить нельзя почти нигде

Из 135 брендов пригодную ценовую подсказку имеют **11**. У остальных либо
сравнить не с чем (`пар = 0`), либо сравнение было только на одном OE, либо
отношения по разным OE расходятся в разы.

Проверено вручную на `Volkswagen`:

| OE | VW: n, медиана | KEMP: n, медиана | отношение |
|---|---|---|---:|
| 09G409061 | 26 · 1040.00 | 2 · 1285.20 | 0.8092 |
| 1F0129620 | 1 · 2758.57 | 1 · 239.62 | 11.5123 |
| 7E0905865 | 2 · 4697.67 | 10 · 285.60 | 16.4484 |
| 7L6127434A | 1 · 2914.00 | 3 · 423.50 | 6.8808 |

Медиана = 9.1965 — арифметически верно и описательно бессмысленно: KEMP за
285 грн против Volkswagen за 4698 грн по одному OE — это разные детали, а не
премия уровня. Ровно то, что §2.2 называет грязью в данных, а не открытием.

Поэтому рядом с медианой в листе идут `ratio_min`, `ratio_max`, `ratio_spread`
и флаг `ratio_is_trustworthy`. Порог — разброс `4.0x`: он выше всей полосы
здравого смысла §2.2 (OEM максимум 4.0x, AM_B около 1.0x, шире настоящий
уровень не бывает) и ниже 20-кратных разбросов, которые дают грязные пары.
Флаг только помечает строку — ничего не фильтрует и ничего не присваивает.

**Практический вывод для разметки:** tier ставить по знанию рынка и по ссылкам
на карточки, а не по колонке «к KEMP». Там, где стоит ⚠, колонку игнорировать.

## 4. Два набора наблюдений, которые нельзя путать (§2.2)

| набор | свои магазины | KEMP | б/у | нужен для |
|---|---|---|---|---|
| конкурентный | исключены | исключён | исключён | что просит конкурент |
| якорь KEMP | **включены** | только KEMP | исключён | знаменатель отношения |

Это не формальность. Измерено: **77 из 79** наблюдений якоря — карточки
собственных магазинов заказчика. Исключи мы их «для единообразия», якорь
схлопнулся бы до 2 наблюдений и отношений не осталось бы почти нигде.

Различие зафиксировано тестами, как требует план:
`test_kemp_is_the_anchor_but_never_a_competitor`,
`test_own_store_kemp_listing_still_anchors_the_ratio`.

Идентичность OE пересчитывается из полей самого предложения, а не берётся из
цепочки ворот: цепочка останавливается на первом терминальном гейте, поэтому
карточка своего магазина до гейта идентичности не доходит и молча выпала бы
из якоря. Согласованность с воротами закреплена тестом
`test_identity_lane_agrees_with_the_production_gate`.

## 5. Найденный дефект: повтор прогона удваивал счётчики

В БД оказалось два полных прогона по одним и тем же 30 OE (16:10–16:24 и
16:51–16:54 — независимая перепроверка Гейта 1). 32 из 33 запросов имеют больше
одного завершённого прогона.

Первая версия листа считала каждое появление объявления отдельным
предложением: `ELRING` — 68 предложений при 34 продавцах, `Polcar` — 74 при 8.

Исправлено: наблюдения дедуплицируются по паре `(целевой OE, listing_id)`,
побеждает самое свежее. Счётчики перестали зависеть от того, сколько раз
гоняли замер. Закреплено тестом
`test_worksheet_counts_are_stable_when_a_batch_is_replayed`.

## 6. Пункт 2.3 — валидатор проверен на живых файлах

Схема черновика содержит ловушку, о которой человека надо предупредить: в
неутверждённой записи `evidence` — это словарь статистики, а для **активации**
загрузчик требует `evidence` в виде непустого списка https-ссылок на prom.ua.
Поэтому генератор сразу кладёт ссылки списком, а статистику — под отдельный
ключ `statistics`, который загрузчик игнорирует.

Проверка fail-closed:

| файл | результат | код возврата |
|---|---|---:|
| `config/brands.yaml` (текущий) | принят, активных не-KEMP `0` | 0 |
| сгенерированный черновик | принят, активных не-KEMP `0` | 0 |
| VAG утверждён полностью | принят, `VAG: oem` активен | 0 |
| то же, но без `approved_by` в записи | **отклонён**: `brands[1].approved_by must be a non-empty string` | 1 |
| запись утверждена, политика документа — нет | **отклонён**: `brands[1] is approved while domain policy is unapproved` | 1 |

Отклоняется весь файл целиком, а не отдельная запись. Частично оформленное
утверждение не активируется молча.

Ещё 11 вариантов недооформления закреплены тестом
`test_incomplete_approval_is_refused_whole_file`: пустой evidence, словарь
вместо списка, http вместо https, чужой домен, дата не по ISO, `tier: unknown`,
`tier: kemp` для не-KEMP бренда, нулевая confidence.

## 7. Что делать человеку (пункт 2.2)

1. Открыть `brands_review_worksheet.csv`, заполнить колонку `tier_TO_FILL`
   для брендов, которые действительно знаете. Начинать сверху — там бренды,
   разблокирующие больше всего позиций.
2. Перенести решения в `brands_draft.yaml`: `tier`, `confidence`, `approved`,
   `approved_by`, `approved_at`. Ссылки в `evidence` уже проставлены —
   проверьте, что они ведут на ту деталь, и замените, если нет.
3. Вверху файла: `domain_policy_approved: true`, `approved_by`, `approved_at`.
4. Проверить: `uv run brand-review-worksheet validate --path <файл>`.
   Код `0` и непустой список активных правил — можно класть в
   `backend/config/brands.yaml`.

Размечать все 135 не нужно. Первые 10–15 строк листа закрывают основную массу
`TIER_UNKNOWN`; остальное — длинный хвост.

Повторная генерация не затирает работу: `--existing` переносит уже принятые
решения, обновляя только статистику
(`test_regeneration_preserves_an_earlier_human_decision`).

## СТОП-ГЕЙТ 2 — НЕ ДОСТИГНУТ

Таблица гейта требует колонку «после словаря»:

```
                   до словаря   после словаря
COMPARABLE              0             ?
REVIEW                 25             ?
SKIP                    4             ?
```

Колонка «после» не может быть заполнена, пока человек не проставил tier'ы:
активных не-KEMP правил `0`, поэтому повторный прогон (2.4) дал бы ровно те же
числа. Заполнять её самому — значит проставить tier'ы за владельца, что
мета-правило 3 прямо запрещает.

Инструменты готовы, ход за человеком.
