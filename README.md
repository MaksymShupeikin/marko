# Metis — AI Agent Project Guide

## Цель проекта

Metis — полуавтоматический инструмент ценовых рекомендаций для магазина автозапчастей на Prom.ua.

Система должна:

1. Искать предложения конкурентов по точному OE-номеру.
2. Исключать б/у товары.
3. Исключать магазины заказчика и связанные storefronts.
4. Классифицировать уровень товара конкурента:
   - `original_oe`
   - `recognized_brand`
   - `generic_analogue`
   - `unknown`
5. Сравнивать товар клиента преимущественно с товарами сопоставимого уровня.
6. Для ходовых товаров находить возможности повышения цены.
7. Для залежалых товаров предлагать снижение цены с учетом разрешенного клиентом убытка.
8. Формировать понятную рекомендацию со ссылками на конкурентов.
9. Помечать случаи с недостатком данных как `manual_review_required`.
10. Всегда оставлять финальное решение человеку.

## Главный scope текущего MVP

Основной pipeline:

```text
OE normalization
→ Prom.ua candidate collection
→ exact OE matching
→ used offer exclusion
→ own/related seller exclusion
→ seller-group deduplication
→ tier classification
→ same-tier price analysis
→ pricing recommendation
→ report with competitor links
→ human review
```

Точный OE является главным ключом автоматического сопоставления.

Если у кандидата нет точного OE исходного товара, использовать статус:

```text
not_in_scope_for_automatic_matching
```

Не пытаться автоматически доказывать совместимость такого товара через внешние кроссы в рамках текущего MVP.

## Что не входит в текущий MVP

Не реализовывать без отдельного согласования:

- автоматические коллекторы Avto.pro/Exist.ua без зарегистрированной политики доступа;
- автоматическую публикацию цен;
- интеграцию с 1С;
- автоматическое изменение цен в магазине;
- сопоставление аналогов по разным OE или артикулам;
- полноценную замену TecDoc;
- обязательные интеграции PartSouq и 7zap;
- VIN matching;
- Vision-проверку применимости;
- сложную ML-модель fitment;
- массовое копирование внешних каталогов.

PartSouq, 7zap, официальные каталоги производителей и LLM-поиск по кроссам относятся к возможному будущему модулю `Metis Fitment Intelligence`, а не к обязательному scope `Metis OE Pricing MVP`.

Avto.pro и Exist.ua присутствуют только в query-level source-routing для поиска
кандидатов по уже подтверждённому номеру. Они не авторизованы автоматически и
не считаются независимыми друг от друга без доказанного различия upstream;
cross влияет на pricing scope только после повторной проверки persisted
claim/document, актуальной политики источника и source/human confirmation.

## Важные особенности Prom.ua

Блоки Prom.ua:

- `Цей товар у інших продавців`
- `Схоже в інших продавців`

являются только источниками кандидатов, а не готовым списком независимых конкурентов.

Они могут содержать:

- магазины того же владельца;
- дубли карточек;
- левую деталь вместо правой;
- переднюю деталь вместо задней;
- оригинал вместе с бюджетным аналогом;
- б/у товары;
- цену за комплект вместо цены за штуку;
- ошибочные OE и описания.

Известные магазины заказчика:

```text
KEMP
Parts Avto
АвтоБуст
ПРОФПАРТС
```

Их предложения не должны попадать во внешнюю рыночную статистику.

## Правила сопоставления

Нормализовать OE детерминированно:

```python
def normalize_oe(value: str | None) -> str:
    if not value:
        return ""

    return "".join(
        character
        for character in value.upper().strip()
        if character.isalnum()
    )
```

Пример:

```text
48530-89025 → 4853089025
```

Сохранять и исходное, и нормализованное значение.

Запрещено:

- fuzzy matching OE;
- сравнение только части номера;
- удаление leading zero;
- принятие похожего названия за доказательство совместимости.

## Фильтрация предложений

Предложение можно включать в основной ценовой расчет только если:

```text
exact_oe_match = true
condition = new
seller_relation = independent
price_is_valid = true
quantity_is_normalized = true
product_tier_is_comparable = true
```

Статусы продавца:

```text
own
related
possibly_related
independent
unknown
```

Правила:

- `own` — исключить;
- `related` — исключить;
- `possibly_related` — отправить на ручную проверку;
- `independent` — учитывать;
- `unknown` — учитывать осторожно или отправить на проверку.

Одинаковые фотографии или описания сами по себе не доказывают общего владельца.

## Достаточность данных

После очистки считать количество независимых сопоставимых seller groups: `n`.

```text
n = 0 → insufficient_data
n = 1 → single_market_reference + manual_review_required
n = 2 → low_confidence_recommendation
n ≥ 3 → normal_market_recommendation
```

Не выдумывать рыночную цену при недостатке данных.

## Логика цены

### Ходовой товар

Если сопоставимый рынок находится выше текущей цены, система может предложить повышение, сохраняя конкурентный буфер.

```text
market_target = lower_market_reference × (1 - competitive_buffer)
```

Не отправлять рекомендации из-за незначительных колебаний. Использовать настраиваемый `deadband`, например 3–5%.

### Залежалый товар

Товар вручную помечается клиентом как `stale`.

Система может предлагать снижение до конкурентного уровня и учитывать разрешенный убыток.

Если себестоимость не задана:

```text
margin_safety = unknown
manual_review_required = true
```

## Конфиденциальность себестоимости

Себестоимость вводит клиент.

Она не должна попадать:

- в backend API;
- в server logs;
- в analytics;
- в error tracking;
- в LLM-запросы;
- разработчикам.

Предпочтительная схема:

```text
Backend calculates market data
→ client device stores cost price locally
→ client device calculates margin/loss limits
```

## Human-in-the-loop

Metis не является автопрайсером.

Система только рекомендует. Пользователь должен иметь возможность:

```text
accept
accept_with_modified_price
reject
defer
request_additional_research
mark_candidate_compatible
mark_candidate_incompatible
mark_seller_as_own
mark_seller_as_related
```

Каждое решение пользователя сохраняется как feedback.

## Первый технический этап

До масштабирования провести замер на 30 стратифицированных SKU:

```text
10 ходовых
10 обычных
10 залежалых или редких
```

Измерить:

- raw offers;
- exact OE matches;
- own seller offers;
- independent new offers;
- same-tier offers;
- долю SKU с 0, 1, 2 и 3+ пригодными конкурентами;
- долю случаев `manual_review_required`.

Главный риск проекта:

```text
Достаточно ли на Prom.ua независимых новых предложений с тем же OE для полезных ценовых рекомендаций?
```

## Правила для ИИ-агента

ИИ-агент обязан:

1. Следовать согласованному scope, а не расширять его молча.
2. Не упрощать задачу до сравнения только названий.
3. Не выдумывать OE, цены, продавцов, tiers или связи магазинов.
4. Явно отделять факт, предположение и неопределенность.
5. Использовать LLM для извлечения и классификации текста.
6. Использовать детерминированный код для нормализации, фильтров, математики и расчета цены.
7. Показывать причину включения или исключения каждого предложения.
8. Сохранять ссылки на конкурентов.
9. Не менять цену без подтверждения человека.
10. Не превращать будущие R&D-идеи в обязательства текущего MVP.

## Критерий хорошего результата

Качество Metis определяется не количеством AI-компонентов, а тем, насколько система:

- правильно исключает магазины заказчика;
- не смешивает несопоставимые товары;
- честно сообщает о нехватке данных;
- объясняет расчет;
- предоставляет проверяемые ссылки;
- экономит время продавца;
- помогает находить наиболее финансово значимые изменения цен.
